# Codex 与 Hermes 工具能力借鉴与适配计划

## 目的

在不复制闭源实现、不过度改变拾光现有前后端事件协议的前提下，借鉴 Codex 的受控执行体验与 Hermes 的反思、记忆和工具编排思路，完善拾光的工具平台。

本计划的“借鉴”仅指公开文档、许可证明确的开源代码和可观察产品模式；所有代码以拾光自己的 TypeScript、Electron、SQLite、项目/工作区/会话模型重新实现。

## 已有基础

- Hermes 风格反思技能、规则写入审批与记忆服务。
- 工具契约：风险、审批模式、成本、阶段、推荐前后置工具与完成信号。
- MCP 适配、响应卡、审批卡、工具事件卡。
- ExecutionGrant、执行权限预设、运行预算、检查点和审批范围数据模型。

因此不导入另一套 Agent 框架；只补齐已有基础尚未覆盖的能力。

## 借鉴映射

| 借鉴方向 | Codex / Hermes 的可取模式 | 拾光适配方式 |
| --- | --- | --- |
| 工具安全 | 明确沙箱、网络、审批和工作区边界 | ExecutionGrant 按读、写、终端、网络判断；界面显示实际权限而非笼统“已授权” |
| 工具目录 | 工具能力声明、参数 Schema、风险元数据 | 扩展现有 ToolContract，不引入第二注册表 |
| 反思学习 | 把用户纠正转成经确认的可复用规则 | 保留 hermes_reflection_coach，新增来源、置信度、失效与删除入口 |
| 长任务 | 状态、检查点、恢复与结果证据 | Task / Run / Checkpoint / Artifact 形成单一恢复链路 |
| 工具失败 | 区分可重试、需审批、需用户输入和永久失败 | 工具健康度、有限重试、结构化恢复建议和停止条件 |
| 供应商工具调用 | 原生 tool use/function calling，统一前端事件 | Anthropic、Gemini 适配成现有 tool_call/tool_result/tool_pipeline |

## 不能复制的内容

- Codex、Hermes 或第三方产品的品牌、服务端协议、私有提示词与闭源代码。
- 未确认许可证的插件、工具定义和模型配置。
- 直接执行从外部 Agent 导入的脚本；导入后必须经过工具注册、权限声明与人工审核。

## 实施阶段

### A. 完成执行授权与审批复用

1. 审批卡增加范围选择：仅本次、当前任务、当前工作区。
2. 删除、移动、Git push、外部发布、凭据与全局安装强制仅本次。
3. 当前任务/工作区授权保存为可撤销规则，并显示到工作区设置。
4. 审批卡显示：工具、目标、工作区、网络域名、数据去向、风险和实际执行预设。

验收：相同低风险写入在被授权范围内不重复打断；高风险操作每次仍需确认。

### B. 工具健康度与有限恢复

1. 工具注册表记录最近成功、失败类别、延迟、版本和提供方。
2. 只对幂等、无外部副作用的网络超时/限流执行有限退避重试。
3. 工具连续失败、无进展或预算耗尽时转为 blocked，并写入检查点。
4. 在工具卡中显示“重试、换工具、请求用户输入、停止”的恢复建议。

验收：写入、提交和发布不会被静默重试；失败不会无限循环。

### C. Hermes 记忆完善

1. 区分候选记忆、已确认记忆、已验证事实和失效记忆。
2. 记忆中心显示来源、范围、置信度、最后验证时间、任务引用与删除入口。
3. 任务开始时只注入相关工作区记忆；当前指令和文件/测试事实始终优先。
4. 不保存密钥、Cookie、密码、私钥和完整终端输出。

验收：用户能解释、编辑、删除每条长期记忆；错误记忆不会覆盖当前事实。

### D. Provider 与 MCP 统一工具层

1. Anthropic 原生 tool use、Gemini function calling 适配为统一事件。
2. JSON 动作协议保留为不支持原生调用时的降级路径。
3. MCP 工具展示服务器来源、版本、数据去向、健康状态和所需权限。
4. 每次任务记录实际使用的模型、工具、技能和版本，便于复现。

验收：不同 Provider 的工具调用在前端显示一致，失败可诊断且不会丢失任务状态。

### E. 工具导入与技能生态（最后执行）

1. 导入外部工具/技能时解析 manifest，展示许可证、维护者、文件范围、联网需求和数据去向。
2. 工具先以禁用状态安装，通过审核后才可供模型选择。
3. 工作区可固定工具版本、撤销授权、停用和回滚。
4. 导出脱敏诊断包，支持复现工具错误而不泄露任务内容。

验收：外部工具无法绕过 ExecutionGrant、审批、工作区边界或敏感数据打码。

## 执行顺序

1. A：审批复用与高风险单次确认。
2. B：工具健康度、有限重试和阻塞恢复。
3. C：记忆中心与候选审核。
4. D：Anthropic/Gemini/MCP 统一工具层。
5. E：受审核的外部工具与技能导入。

# Codex 电影感前端重设计规格

## 目标

在不改变现有前后端能力和数据结构的前提下，恢复此前确认的视觉方向：以 Codex 的信息架构和操作密度为骨架，使用深色电影感、暖橙色微光和 11 号“工作窗口”图标形成拾光 Agent 自己的辨识度。

本次是视觉与交互重构，不是普通换色，也不复刻 Codex 品牌。用户打开应用后应立即看出新版层级、密度和对话中心结构。

## 已确认的设计决策

- 保留 11 号“工作窗口”图标，不再进行图标轮选。
- 主层级固定为 `项目 → 工作区 → 任务/会话`。
- 工作区决定文件修改范围；界面始终展示当前项目和工作区。
- 任务行目标高度为 32–34px，纵向紧凑。
- 中央区域以对话为主，响应、思考、工具、审批、错误和系统消息进入同一时间流。
- 运行详情按需展开，不常驻挤压聊天区域。
- 深色电影感和暖橙微光是品牌主题；避免蓝紫科技渐变、纯黑扁平化和大面积玻璃卡片。

## 视觉语言

### 色彩

| 用途 | 建议值 | 说明 |
| --- | --- | --- |
| 应用底色 | `#141311` | 带少量暖色的近黑色 |
| 导航底色 | `#171614` | 比主背景略亮 |
| 工作区栏 | `#1B1917` | 建立左侧层级，但不做悬浮卡片 |
| 输入框/卡片 | `#24211E` | 对话和控件的主要承载面 |
| 主要文字 | `#F1ECE5` | 暖白色，降低纯白刺眼感 |
| 次要文字 | `#A19A91` | 路径、时间和说明 |
| 品牌强调 | `#D9954E` | 暖橙色，只用于选中、运行和关键入口 |
| 微光 | `rgba(217,149,78,.20)` | 小范围边缘光，不做大面积渐变 |
| 成功 | `#64BD88` | 工具成功、连接正常 |
| 风险 | `#D46C68` | 错误与危险动作 |

背景可以有极弱颗粒和局部暖光，但不能影响文字对比度。面板之间主要用色阶和 1px 分隔线区分，避免厚重阴影和大圆角。

### 形状与密度

- 主面板不使用悬浮大卡片；应用铺满窗口。
- 普通控件圆角 6–8px，对话输入框和重要卡片圆角 12–14px。
- 左侧主导航宽 52px，项目/工作区栏默认宽 280px，可拖动到 240–380px。
- 顶部会话栏高度约 56px，底部状态栏高度 24–26px。
- 动画只用于运行状态、待确认提醒和轻微 hover，时长 120–180ms。

## 页面结构

```text
┌──────┬────────────────────────┬──────────────────────────────────────┐
│ 图标 │ 项目 / 工作区 / 任务   │ 当前项目 / 工作区          操作菜单 │
│ 导航 │                        ├──────────────────────────────────────┤
│      │ 项目 A                 │                                      │
│ 会话 │  └ 工作区 A            │            对话时间流                │
│ 审批 │     ├ 任务 1           │ 响应 / 思考 / 工具 / 审批 / 错误卡   │
│ 新建 │     └ 任务 2           │                                      │
│      │  └ 工作区 B            ├──────────────────────────────────────┤
│ 设置 │                        │         浮岛式输入框                  │
├──────┴────────────────────────┴──────────────────────────────────────┤
│ 当前工作区 · 模型 · Token · 连接状态                                │
└─────────────────────────────────────────────────────────────────────┘
```

### 一级导航

- 顶部显示 11 号图标，尺寸 30–32px。
- 会话、审批、新建和设置使用简洁线性图标。
- 当前入口使用暖橙色 2px 左边标记和深色选中底，不使用整块高饱和颜色。
- 待审批通过一个小橙点或数字徽标提示。

### 项目与工作区栏

- 顶部显示当前项目、当前工作区和路径尾部，右侧放添加工作区、设置、新建任务。
- 搜索框保持单行紧凑；筛选项横向排列。
- 项目作为小型分组标题。
- 工作区行显示名称、路径和可用状态；选中后以轻微暖色底和橙色标识强调。
- 任务行仅保留标题、状态点和必要的固定标记；摘要在 hover 或菜单中查看。
- 新建任务入口属于当前工作区，避免让用户误解任务的修改范围。

### 对话顶部

- 第一行始终显示 `项目 / 工作区`。
- 第二行显示任务标题。
- 重试、分支、归档和运行详情归入右侧紧凑操作区；低频操作进入更多菜单。
- 工作区不可用时，顶部直接显示风险提示并禁用会触发修改的发送行为。

### 对话时间流

- 助手响应采用无外框或极弱底色，最大宽度约 780px。
- 用户消息靠右，使用暖棕色半透明气泡，最大宽度约 620px。
- 思考卡默认折叠，颜色和层级弱于最终响应。
- 工具调用与结果成对呈现：标题行显示工具、状态和耗时；展开后左右展示输入与结果。
- 错误卡使用红色左边标，提供复制、写入修复提示、重试和分支入口。
- 上下文压缩等系统信息使用低对比度窄卡，不抢占主响应层级。

### 操作确认

- 审批卡在相关工具调用位置原位出现，同时进入“审批”汇总页。
- 清晰展示动作名称、目标、工作区、影响范围、命令或差异预览以及风险说明。
- “拒绝”使用中性按钮，“允许”使用暖橙主按钮；危险动作不能只靠颜色区分。
- 提交期间锁定按钮，完成后立刻更新卡片、待审数字和运行状态。

### 输入区

- 使用居中的浮岛式输入框，最大宽度约 900px。
- 文本区无内层边框；附件、模型、调试和 Token 位于底部工具行。
- 发送按钮使用暖白或暖橙，运行中根据状态切换为“补充”或“暂停”。
- 拖入附件时只在输入框范围显示虚线提示，不覆盖整个页面。

### 运行检查器

- 默认关闭，从对话顶部打开。
- 以右侧抽屉或覆盖面板展示当前阶段、事件统计、运行历史、失败诊断和产物。
- 关闭后对话宽度恢复，不留下空白栏。

## 状态设计

- 无项目：中央提供“创建项目”入口。
- 无工作区：先引导选择目录并创建工作区，再允许新建任务。
- 无任务：在当前工作区内显示单一的新建任务入口。
- 空对话：展示当前工作区范围和可直接输入的提示，不使用营销式大标题。
- 运行中：工具状态点轻微呼吸，顶部显示阶段；禁止重复触发运行操作。
- 待审批：对话原位卡片、导航徽标和顶部状态保持一致。
- 失败：保留输入、附件和上下文，提供明确恢复动作。
- 工作区失效：历史可读，修改和运行入口禁用，并提供重新定位目录入口。

## 复用与改造边界

### 直接复用

- `ActivityFeed` 及事件转换模型。
- `ApprovalCard` 和 `ApprovalCenter` 的数据与行为。
- `RunInspector` 的运行、失败和产物能力。
- 项目、工作区、会话选择和生命周期逻辑。
- 当前后端 IPC、实时订阅和工作区权限模型。

### 需要调整

- `App.tsx`：只整理壳层结构、导航图标和低频操作入口，不改业务调用。
- `styles.css`：删除相互冲突的多轮主题覆盖，建立单一设计令牌和壳层样式。
- `activity.css`：统一暖色令牌、间距和卡片宽度。
- `approvals.css`：统一按钮、风险层级和工作区范围展示。
- `run-inspector.css`：改为按需右侧抽屉，并与主界面使用相同色彩和边框。

## 实施顺序

1. 固化颜色、间距、圆角、字体和动画令牌，删除最终覆盖式临时主题。
2. 重构应用壳层和项目/工作区/任务栏，确保任务行高度和层级正确。
3. 重构对话顶部、时间流宽度和输入浮岛。
4. 统一响应、思考、工具、审批、错误和系统卡片。
5. 将运行详情整理为按需抽屉，完善空状态、失效状态和窄窗口适配。
6. 使用真实桌面桥接数据进行手工验收，并完成自动化测试、类型检查和打包。

## 验收标准

- 首屏能明显识别为新界面，不再出现旧版大圆角玻璃三栏。
- 视觉为暖色电影感，而非蓝紫科技风或纯灰黑 Codex 仿制。
- 11 号图标、项目、工作区和任务层级完整可见。
- 任务行实际高度不超过 34px，列表在 1080p 高度下能显示足够多任务。
- 当前项目和工作区在对话顶部与状态栏均可确认。
- 响应、思考、工具调用/结果、审批、错误和系统事件均能由真实后端事件正确渲染。
- 审批通过/拒绝、取消、重试、分支、附件、模型切换、设置和产物操作与改版前功能等价。
- 窗口宽度低于 760px 时隐藏项目/工作区栏，但主导航、对话和输入仍可使用。
- UI 测试、Electron 测试、类型检查、桌面构建和 Windows 打包全部通过。

## 非目标

- 不改变数据库、工作区权限、Provider 协议或 Agent 执行引擎。
- 不新增云同步、多人协作或移动端布局。
- 不在本次改造中重新选择品牌图标和主题方向。
- 不以堆叠新的 CSS 覆盖层作为最终实现；必须收敛成可维护的单一主题。

# 拾光 Agent｜Codex 式前端重构设计

## 目标

将当前以设置面板和功能区堆叠为主的桌面界面，重构为“聊天优先、信息按需展开”的工作台。参考 Codex 的信息架构与操作节奏，不复制其品牌、资产或实现。

成功标准：用户始终知道当前项目、工作区和会话；聊天不被任务与管理面板遮挡；任务、审批、工具、记忆与产物均可快速打开并可回到对话。

## 已确认的视觉方向

- 深色基底，保留拾光现有橙金强调色与克制的彗星力量感。
- 减少描边、发光与大面积卡片；用留白、排版和单一强调色建立层级。
- 不替换“拾光 Agent”产品名称或既有工作区安全模型。

Figma 评审稿：[拾光 Agent｜Codex 式前端重构方案](https://www.figma.com/design/vdYrklJDNZZfIzn0X30TP4)。

## 信息架构

```text
App shell
├─ 左侧工作区导航（常驻）
│  └─ 项目 → 工作区 → 会话
├─ 主对话区（常驻、最高优先级）
│  ├─ 紧凑会话顶部栏
│  ├─ 单行任务状态条
│  ├─ 消息、响应卡、审批卡、工具卡
│  └─ 输入框
└─ 右侧上下文抽屉（按需打开）
   ├─ 任务：计划、检查点、证据、预算、运行控制
   ├─ 工具：调用、健康度、失败与恢复建议
   ├─ 审批：待处理与可复用范围
   ├─ 产物：文件、链接、测试与结论
   └─ 记忆：候选、有效、失效与来源
```

## 关键界面

### 1. 主对话

左侧栏只显示层级与轻量状态：项目、工作区、会话标题和运行点。它不再承载任务细节、记忆或审批操作。

顶部栏显示工作区面包屑、会话标题、运行状态与一个紧凑菜单。任务条固定为一行，仅显示当前步骤、进度和“任务详情”入口。任务没有运行时，任务条不占据空间。

消息区为主阅读面；响应、审批与工具活动沿用现有前后端事件契约。输入框停靠底部，保留工作区和模型提示，但不引入新的 Provider 分支。

### 2. 任务抽屉

右侧抽屉由“任务详情”或快捷键打开，默认宽度 376px。抽屉显示：任务状态、计划步骤、预算、检查点、执行证据、暂停/继续/取消。关闭后不改变会话或运行状态。

在窄窗口下，抽屉覆盖主区右侧而不是压缩左侧工作区导航；打开时保留对话可见区域。所有可执行动作维持现有审批与 IPC 调用。

### 3. 记忆中心

记忆从设置抽离，成为右侧抽屉的一个上下文页，并保留独立入口。按“待确认 / 有效 / 已失效”筛选，显示范围、来源、置信度、验证时间和内容。

候选只能保留或忽略；有效记忆可编辑、标记失效或删除；失效记忆仅用于审计且不注入后续任务。所有操作严格限制在当前工作区。

## 组件与状态边界

将当前 `ui/src/App.tsx` 中的视觉壳拆分为：

- `WorkspaceSidebar`：项目、工作区、会话选择。
- `ConversationPane`：标题、任务条、对话时间线与输入框。
- `ContextDrawer`：抽屉状态与标签切换。
- `TaskPanel`、`ToolPanel`、`ApprovalPanel`、`ArtifactPanel`、`MemoryPanel`：各自只消费已有 bridge 数据。

Bridge、Electron IPC、后端服务与数据模型不因布局重构改变；新增 UI 状态只包括抽屉开关、当前标签和窄屏覆盖模式。

## 交互与可访问性

- `Esc` 关闭抽屉；焦点回到触发按钮。
- 任务条、状态点、审批状态均有文字，不只依赖颜色。
- 键盘可浏览会话、打开任务抽屉与聚焦输入框。
- 1366×768、1440×900、1920×1080 三种窗口尺寸必须没有遮挡、横向溢出或不可达操作。

## 验收与测试

- 现有 UI、Electron、核心测试继续通过。
- 为抽屉开关、会话切换不改日期、工作区隔离新增 UI 测试。
- 保留响应卡、工具卡、审批卡和记忆候选渲染；只改变其容器与入口。
- 用 Figma 三屏与打包前桌面截图完成视觉回归。

## 不在本次范围

- 不改变 Agent 循环、Provider 协议、工具权限或数据库模式。
- 不增加云同步、多人协作、远程执行或新的外部插件能力。

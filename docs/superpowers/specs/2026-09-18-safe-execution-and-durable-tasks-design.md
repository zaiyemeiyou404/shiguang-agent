# 安全执行与可恢复任务交付设计规格

## 背景

拾光已经具备本地工作区、项目级 profile、工具审批、运行事件、产物、长期记忆和多 Provider 能力。当前主要短板不再是“能否调用工具”，而是 Agent 在真实项目中能否被安全授权、长时间运行、被中断后恢复，以及让用户清楚审查每一个结果。

本规格借鉴公开产品的共同模式：Codex 的工作区隔离、网络默认关闭和审批策略；Claude Code 的权限模式、工具白名单和续跑；Cursor 的后台任务可见性。实现目标是形成拾光自己的本地优先方案，不复制其他产品的品牌或协议。

## 目标

1. 把“工作区目录”升级为真正可执行的安全边界，而不只是一条终端 `cwd` 约定。
2. 把会话中的任务变成用户可见、可暂停、可恢复、可验收的持久对象。
3. 让网络、终端、写入、Git 和外部工具的权限有可理解的默认值与明确升级路径。
4. 保持现有项目 → 工作区 → 会话、审批卡、事件卡和 Provider 体系兼容。
5. 为桌面端建立可重复的端到端验收、恢复和发布流程。

## 非目标

- 不在本期实现云端多人协作、远程托管 Agent 或账号系统。
- 不把任何命令都塞进容器；用户可明确选择受控的完整访问模式。
- 不改变已有会话、工作区、记忆或审批数据的语义。
- 不将浏览器自动化作为第一阶段的默认能力。

## 设计原则

- 默认最小权限：读取、修改、终端、网络和外部副作用是独立能力。
- 先展示范围，再要求批准：用户必须先看到目录、网络域名、命令和预计影响。
- 审批是策略，不只是弹窗：允许单次、当前任务、当前工作区三种可解释的授权期限。
- 每次长任务都有检查点；崩溃、暂停和恢复不会丢失已知事实、草稿和产物。
- 任务完成必须有证据：修改摘要、验证结果和未完成项应一起呈现。

## 一、执行权限与沙箱

### 1.1 权限预设

每个工作区保存默认预设，任务可在开始前临时降级或升级：

| 预设 | 文件 | 命令 | 网络 | 典型场景 |
| --- | --- | --- | --- |
| 只读 | 读取工作区 | 禁止 | 禁止 | 代码理解、评审 |
| 工作区修改 | 工作区内读写 | 受限命令，逐次确认 | 禁止 | 修复、重构 |
| 工作区修改 + 网络 | 工作区内读写 | 受限命令，逐次确认 | 仅域名白名单 | 安装依赖、查官方文档 |
| 完整访问 | 用户显式指定范围 | 用户逐次确认 | 用户逐次确认 | 需要真实宿主能力的任务 |

### 1.2 执行代理

- 所有 `run_terminal_command`、后台进程、MCP 执行工具都通过一个 Execution Broker 启动。
- Broker 接收不可变 `ExecutionGrant`：工作区根、允许写入根、网络规则、时间/资源上限和审批 ID。
- Windows 第一阶段优先使用 WSL sandbox 或受限子进程；无法隔离时必须在审批卡标记为“宿主完整访问”，不能伪装为沙箱。
- 默认关闭网络；需要网络时只允许当前任务批准的域名列表。Web 搜索、抓取、MCP 和包管理应分别显示目标域名。
- 写入前继续使用现有 diff 预览；终端命令在开始、超时、结束时记录 cwd、退出码和资源摘要。

### 1.3 审批策略

新增 `ApprovalScope`：`once`、`task`、`workspace`。所有持久授权都记录原因、创建时间、过期时间和可撤销入口。

审批卡增加：

- 实际执行模式：沙箱 / 受限宿主 / 完整宿主。
- 可写目录、网络域名、命令和预计副作用。
- “仅这次”“本任务内允许”“查看并修改工作区规则”三个明确动作。
- 对 Git push、删除、安装全局依赖、外部发布等高风险动作，强制 `once`。

## 二、持久任务面板与检查点

### 2.1 任务对象

后端已持久化 `Task`、`Run`、`Event` 和 `Artifact`，本期将其显式呈现在会话中：

- 会话下显示任务列表；每个任务有目标、状态、当前步骤、验证状态和最近运行。
- 新消息默认创建或关联一个任务，用户可拆分、合并、归档任务。
- 任务状态为：`planned`、`running`、`waiting_approval`、`waiting_user`、`blocked`、`verifying`、`completed`、`cancelled`。
- 每个任务显示“完成证据”：修改文件、运行验证、产物和最后一条 Agent 结论。

### 2.2 检查点与恢复

- 工具调用完成、审批等待、验证完成和模型上下文压缩后自动写入检查点。
- 检查点包含：任务计划、已确认事实、待执行步骤、有效授权、草稿、附件引用、运行指针和验证摘要。
- 应用重启后，不自动重新执行命令；任务恢复到“可继续”状态，由用户确认后继续。
- 用户可从任意检查点分支；分支继承工作区和只读上下文，不继承尚未确认的授权。

### 2.3 前端布局

- 保持项目 → 工作区 → 会话主层级。
- 当前会话标题下增加一个可折叠“任务”条；默认只显示当前任务、状态和下一步。
- 运行检查器扩展为“任务检查器”：计划、检查点、运行历史、产物、失败证据和恢复入口在同一抽屉内。
- 聊天流仍是主要阅读区；任务面板不能挤压响应卡和审批卡。

## 三、模型与工具协议可靠性

### 3.1 Provider 原生工具调用

- OpenAI-compatible 现有 native tool calling 保持不变。
- 为 Anthropic 实现 native tool use；为 Gemini 实现 function calling。
- 统一把所有 Provider 的工具调用转成当前 `tool_call` / `tool_result` / `tool_pipeline` 事件，前端无需按模型分叉。
- JSON 动作协议继续作为 Provider 不支持原生调用时的降级路径。

### 3.2 结构化失败恢复

- Provider 错误按认证、配额、网络、限流、协议解析、模型拒绝和超时分类。
- 任务检查器提供“重试原请求”“切换模型后继续”“复制诊断”“转为人工处理”动作。
- 不重放有外部副作用的工具；恢复从最后一个安全检查点开始。

## 四、桌面验收、数据保护与发布

### 4.1 端到端验收

新增 Electron E2E 测试覆盖：

- 创建项目、工作区、会话与任务。
- 普通响应、工具调用/结果、审批通过/拒绝和运行恢复。
- 工作区边界、网络拒绝和授权升级。
- 崩溃/重启后的检查点、草稿、附件和审批状态恢复。
- 1280×800、1366×768、1920×1080 三种窗口尺寸的视觉回归，防止侧栏和分隔条遮挡。

### 4.2 数据保护

- 设置中提供“导出数据包”和“从数据包恢复”。
- 导出包包含 SQLite、配置（默认脱敏）、skills、工具模板和可选附件索引。
- 升级前自动创建滚动备份，保留最近 N 个；恢复前展示影响范围。

### 4.3 发布

- 增加应用内“检查更新 / 下载后重启安装”。
- Windows 发布启用应用图标、版本资源和签名配置；未签名时在发布页明确提示。
- CI 在打包前运行核心、UI、Electron 和 E2E 测试；正式 tag 发布安装包、免安装包和校验值。

## 五、浏览器自动化（后续阶段）

浏览器能力不作为默认工具。后续可提供独立的 Browser Session：

- 每个浏览器会话与任务绑定，默认无登录态共享。
- 打开登录态、上传文件、提交表单、下载和外部发布必须逐次审批。
- 页面读取可走现有 `web_fetch`；只有动态页面或用户明确要求操作网页时才启动浏览器。
- 保存站点、当前 URL、下载清单和外部副作用事件，供任务检查器审计。

## 六、记忆系统：可控、可追溯、可遗忘

记忆不是把所有聊天记录永久塞给模型，而是分层保存可复用事实，并且让用户始终知道它从哪里来、何时生效、能否删除。

### 6.1 记忆分层

| 层级 | 生命周期 | 内容 | 作用范围 |
| --- | --- | --- | --- |
| 本轮上下文 | 单次运行 | 当前工具结果、临时推理、未完成步骤 | 仅当前 Run |
| 会话记忆 | 会话存续 | 已确认需求、决定、草稿和对话摘要 | 当前会话 |
| 工作区记忆 | 长期 | 技术栈、目录约定、测试命令、编码规范、常见风险 | 当前工作区 |
| 项目记忆 | 长期 | 产品背景、团队约定、发布流程、共享术语 | 当前项目 |
| 用户偏好 | 长期且可选 | 语言、界面偏好、常用工作方式 | 用户主动启用的全局范围 |

工作区和项目记忆必须带有来源（用户明确说过、文件验证、Agent 推断）、置信度、更新时间和失效条件。模型推断不能直接升级为长期事实；需要用户确认，或被文件/命令结果再次验证。

### 6.2 写入、检索与清理

- 每次任务结束由 Agent 提出“建议记住”的候选项，用户可逐条接受、修改或忽略；不自动保存隐私、凭据、访问令牌和完整终端输出。
- 任务开始时只检索与当前工作区、任务目标和文件路径相关的少量记忆，并在任务检查器中显示“本次已使用的记忆”。
- 提供记忆中心：搜索、按范围筛选、查看来源、固定、编辑、失效、删除和导出；删除立即阻止后续检索，但保留最小化审计标识。
- 记忆与附件、聊天原文分离存储。摘要可重建，原文和敏感数据不能被摘要反向泄露。
- 当记忆冲突时，文件/测试/用户当前指令优先于旧记忆；系统提示用户进行“更新、保留两个版本、删除旧版本”的选择。

## 七、任务循环与自主执行：有预算、会停下、能交接

长任务应运行在明确的循环控制器中，而不是让模型无限续写。循环的每一步均以任务状态、检查点和资源预算作为边界。

### 7.1 任务循环

```text
计划 → 读取上下文/记忆 → 执行一个可验证步骤 → 写入事件和检查点
  ↑                                      ↓
  └──────── 未达成目标且仍有预算 ────────┘
                        ↓
              验证 → 完成 / 等待确认 / 阻塞
```

- 每个 Task 创建 `RunBudget`：最大轮数、最大模型调用数、最大执行时长、最大工具调用数、最大费用/令牌和最大失败重试次数。
- 每轮只允许完成一个清晰子目标：读取、规划、一次工具链、验证或汇报。外部副作用操作后必须先落检查点，再进入下一轮。
- 连续无进展、重复调用相同工具、同一错误超过阈值、预算耗尽、检测到范围漂移时，自动进入 `blocked`，说明证据和建议，而不是继续消耗资源。
- “继续”只能从用户确认或明确的自动恢复策略触发；恢复时展示将要做的下一步、剩余预算和已有变更。
- 支持计划性循环，例如“每 10 分钟检查一次构建状态”，但必须设置结束条件、最长存活时间、通知策略和取消入口；不允许无限后台循环。

### 7.2 子任务与交接

- 一个父任务可拆分出只读研究、实现、验证三个子任务；子任务默认继承工作区边界，但不继承写入、网络或外部发布权限。
- 子任务回传结构化交接包：目标、已验证事实、产物、未解决项、建议下一步和可复用记忆候选项。
- 父任务汇总前必须验证子任务产物；不能把子任务自然语言结论直接当作完成证据。
- 前端在任务条中显示当前循环阶段、已用/剩余预算、等待原因和停止按钮；后台任务必须始终可见、可暂停、可取消。

## 八、工具平台：声明、策略、结果与健康度

工具层需要从“能被模型调用的函数集合”升级为可治理的平台，统一管理内置工具、MCP、技能和用户脚本。

### 8.1 工具注册表

每个工具声明以下元数据：

- 标识、版本、提供方、输入/输出 Schema、幂等性和超时。
- 能力标签：读取文件、写入文件、终端、网络、浏览器、凭据、Git、外部发布。
- 所需最小权限、可用工作区范围、允许的域名/命令策略以及是否支持后台运行。
- 数据去向：本地、远程 API、第三方 MCP；远程工具必须展示提供方和将发送的数据摘要。
- 健康状态、最近失败原因、重试方式和降级路径。

所有工具调用继续归一化为现有事件卡片；新增 `tool_started`、`tool_progress`、`tool_retry`、`tool_blocked`、`tool_cancelled`、`tool_health` 事件，保证旧前端渲染和 Provider 兼容。

### 8.2 工具调用策略

- 工具选择先检查注册表与 `ExecutionGrant`，不满足权限时生成审批卡，不由模型绕过。
- 同类工具保留单一优先级：本地文件读取优先于终端文本解析；官方 API 优先于页面模拟；只读工具优先于写入工具。
- 对网络、安装、删除、Git push、浏览器提交、发送消息等副作用工具强制显示目标与影响；工具返回后把影响摘要写入任务时间线。
- 工具输入和输出经过敏感信息检测，令牌、Cookie、密码和私钥默认打码，且不能进入长期记忆或诊断导出包。
- 失败重试采用工具级策略：只对安全且幂等的调用自动重试；外部提交、写入和支付类操作永不静默重试。

### 8.3 技能与提示模板

- 技能是版本化的工作流说明与工具权限声明，不是可绕过审批的脚本入口。
- 安装/启用技能时展示其所需工具、网络访问、文件范围和维护者；工作区可固定版本或禁用某一技能。
- 任务执行记录实际使用的技能版本与提示模板版本，便于复现、调试和回滚。

## 实施顺序

1. Execution Broker、权限预设、审批范围与网络默认关闭；同时建立工具注册表与敏感信息打码。
2. 任务面板、检查点、重启恢复、任务循环预算与任务级验收结果。
3. 分层记忆、记忆中心、候选写入审核和任务启动时的相关记忆检索。
4. Anthropic / Gemini 原生工具调用、工具健康度及统一恢复策略。
5. Electron E2E、视觉回归、导出恢复、升级发布。
6. 受审批约束的浏览器自动化与计划性后台循环。

## 验收标准

- 在“工作区修改”模式下，命令无法读取或写入未授权目录，且默认无法联网。
- 所有权限升级都能在审批卡和任务时间线上审计、撤销和解释。
- 应用重启后，运行不会自动产生新的副作用；用户能从最后检查点继续。
- 用户能在一个会话中查看并切换多个任务，清楚知道每个任务的完成证据和阻塞原因。
- 用户能查看、编辑、删除本次任务使用或建议写入的记忆；旧记忆不会覆盖当前用户指令或已验证文件事实。
- 每个长任务都显示循环阶段与资源预算；重复无进展、预算耗尽或连续失败时会安全停止并给出交接信息。
- 每次工具调用都能追溯到工具版本、权限、数据去向和任务事件；敏感信息不会显示在卡片、日志、记忆或导出包中。
- Anthropic、Gemini、OpenAI-compatible 的工具调用均能渲染为同一种工具卡。
- CI 自动验证安全边界、审批、恢复、三种窗口尺寸和 Windows 安装包。

# 拾光 Agent 总体完善与交付计划书

## 1. 产品目标

拾光 Agent 是一个以本地项目和工作区为中心的桌面智能协作工具。它应具备类似专业编码 Agent 的连续工作能力，但用户始终能看懂：它在什么范围内工作、正在做什么、记住了什么、会调用什么工具，以及最终是否真正完成。

本计划将已有的界面设计、前后端适配、安全执行、持久任务、记忆、任务循环、工具治理、稳定性和发布能力整合为一条路线。所有新增能力必须保持现有“项目 → 工作区 → 会话”结构、响应卡、操作确认卡、工具卡和多 Provider 兼容。

## 2. 最终用户体验

```text
项目
└─ 工作区（明确可读写范围与默认权限）
   ├─ 会话（聊天、响应卡、审批卡、工具卡）
   ├─ 任务（计划、进度、检查点、证据、恢复）
   ├─ 记忆（可追溯、可编辑、可删除的项目知识）
   └─ 产物（文件、补丁、测试、文档、链接与结论）
```

用户从创建项目开始，选择工作区并连接模型；在会话中发起任务。Agent 仅在获得相应权限后调用工具，任务以有限循环推进，并把每一步、每个产物和验证结果保存在时间线中。用户可以暂停、取消、恢复、搜索或导出任何任务；应用重启、网络失败或模型切换都不会悄悄重复外部副作用。

## 3. 核心原则

1. **工作区是边界。** 读取、写入、终端、网络、浏览器与外部发布分别授权，不能由 `cwd` 约定代替安全控制。
2. **用户先看到影响，再给予许可。** 审批展示目录、命令、域名、数据去向、预期副作用和授权时限。
3. **任务必须可停止、可恢复、可验收。** 每项长工作有预算、检查点、完成证据与明确阻塞原因。
4. **记忆必须可控。** 用户知道哪些信息会被使用或保存，并能追溯、修改、失效、导出与删除。
5. **工具必须可治理。** 内置工具、MCP、技能与脚本接受同样的权限、版本、数据去向和健康度管理。
6. **兼容优先。** 维持既有 UI 事件与响应卡渲染；能力增强不要求前端按模型供应商分支。
7. **本地优先与隐私默认。** 不默认上传会话、文件、密钥或日志；远程服务与遥测均需明确告知和选择。

## 4. 统一能力设计

### 4.1 项目、工作区与前端结构

- 左侧保持项目和工作区树，工作区成为后续任务、记忆、工具权限和产物归属的唯一范围来源。
- 中央保持会话为主要阅读区；当前会话标题下放置紧凑任务条，只展示当前任务状态、下一步和预算。
- 任务检查器以抽屉/面板呈现计划、检查点、运行记录、使用记忆、工具调用、产物和验证，不遮挡响应卡与审批卡。
- 项目/工作区切换、创建、重命名、搜索、最近打开项与快捷键均有明确空状态和错误状态。
- 窄屏、缩放、侧栏拖拽、深色主题和窗口标题栏须通过视觉回归，防止内容跨越分隔线。

### 4.2 执行权限与审批

工作区保存默认预设：只读、工作区修改、工作区修改加网络、完整访问。每次执行由 `ExecutionBroker` 颁发不可变 `ExecutionGrant`，包含工作区根、可写路径、命令限制、域名规则、资源上限与审批 ID。

- 默认网络关闭；联网按任务、域名和用途批准。
- 写入、终端、Git、安装依赖、浏览器、外部发布均为独立能力。
- 审批范围支持一次、当前任务、当前工作区；删除、Git push、全局安装、外部发布永远要求单次确认。
- Windows 优先采用受限子进程或 WSL 沙箱；不能隔离时必须明确标记为“宿主机完整访问”。

### 4.3 任务、循环与检查点

每条用户请求可关联一个持久 `Task`，状态为 `planned`、`running`、`waiting_approval`、`waiting_user`、`blocked`、`verifying`、`completed` 或 `cancelled`。

任务循环固定为“计划 → 读取相关上下文/记忆 → 执行一个可验证步骤 → 记录事件和检查点 → 验证”。每个 Run 有最大时长、模型调用数、工具调用数、重试数、令牌/费用与后台存活时间。

以下情况自动停止并转为 `blocked`：无进展、重复工具错误、预算耗尽、范围变化、权限不足或未确认的外部副作用。重启后任务仅恢复为“可继续”，必须由用户确认后才开始新的执行。

### 4.4 记忆与知识管理

| 层级 | 保存内容 | 有效范围 |
| --- | --- | --- |
| 当前上下文 | 本轮工具结果、草稿、未完成步骤 | 当前 Run |
| 会话记忆 | 已确认需求、决定、会话摘要 | 当前会话 |
| 工作区记忆 | 技术栈、路径约定、测试命令、风险 | 当前工作区 |
| 项目记忆 | 产品术语、发布流程、团队约定 | 当前项目 |
| 用户偏好 | 语言、交互与表达偏好 | 用户主动启用 |

记忆均保存来源、置信度、最后验证和失效状态。任务完成后只生成“建议记住”候选项，用户决定是否采纳。当前用户指令和已验证文件/测试结果永远优先于旧记忆。设置内提供记忆中心与本次使用记忆清单；敏感信息不得进入记忆或导出包。

### 4.5 工具、技能与 Provider

工具注册表统一描述内置工具、MCP、技能与脚本：版本、输入输出 Schema、能力标签、幂等性、超时、数据去向、最小权限、工作区范围、域名规则与健康状态。

- 工具调用先校验注册表和 `ExecutionGrant`；不满足权限时生成审批卡。
- 统一渲染为 `tool_started`、`tool_progress`、`tool_result`、`tool_retry`、`tool_blocked`、`tool_cancelled` 事件，旧工具卡继续可用。
- Anthropic 使用原生 tool use，Gemini 使用 function calling；现有 JSON 动作协议保留为降级路径；前端不按 Provider 分叉。
- 仅对安全、幂等调用自动重试。写入、提交、发送、付款与发布永不静默重试。
- 技能为版本化工作流与权限声明，安装时展示维护者、所需权限、联网和数据去向；技能不能绕过审批。

### 4.6 产物、搜索与诊断

每项任务将文件修改、补丁、图片、命令结果、测试报告、下载项、链接和最终结论归集为 `Artifact`。用户可按项目、工作区、会话、任务、记忆、产物、路径、日期或状态搜索；结果能直接打开、复制、定位或复用。

诊断中心展示版本、平台、数据库健康、Provider 连通性、工具健康、失败任务与崩溃记录。生成的诊断包默认脱敏，并在导出前由用户预览。

### 4.7 稳定性、数据与发布

- 流式消息支持断线重连、事件去重与取消；长会话和日志采用分页/虚拟化。
- 数据库迁移先预检查和备份，失败可回退；升级不得丢失项目、会话、任务、记忆或审批数据。
- 数据与隐私面板展示本地数据类型、位置、占用；支持导出、恢复、清理缓存和按项目删除。
- 正式发行包含 Windows 签名、校验和、变更日志、应用内更新、升级前备份和失败回滚。
- 遥测、崩溃报告和云能力必须说明收集范围并可关闭；不上传密钥、文件正文、完整会话和工具日志。

### 4.8 可访问性与桌面细节

核心操作支持键盘、命令面板和快捷键；审批、弹窗和任务控制具有正确焦点管理。UI 使用语义化结构与实时提示，不能仅依赖颜色表达运行或失败。支持系统字体缩放、深浅主题和中文优先文案。

## 5. 分阶段实施路线

| 阶段 | 主题 | 主要交付物 | 验收重点 |
| --- | --- | --- | --- |
| P0 | 基础兼容与稳定 | 统一事件契约、错误分类、流式去重、数据库迁移备份、视觉回归骨架 | 现有响应卡/审批卡/工具卡与前后端不回归 |
| P1 | 工作区安全与工具治理 | ExecutionBroker、权限预设、审批范围、工具注册表、敏感信息打码 | 未授权目录/网络不可访问，高风险操作均可审计 |
| P2 | 可恢复任务 | 任务条、检查点、RunBudget、暂停/取消/继续、任务检查器、产物中心 | 重启不重放副作用，任务有证据、预算与阻塞原因 |
| P3 | 记忆与模型可靠性 | 分层记忆、记忆中心、候选审核、Provider 原生工具调用、健康度/降级 | 记忆可控可删除，三类 Provider 渲染一致 |
| P4 | 产品体验 | 首次向导、连接管理、搜索、工作区健康、快捷键、无障碍 | 新用户能完成连接，历史与产物能快速找到 |
| P5 | 发布与长期能力 | Electron E2E、数据导出恢复、签名更新回滚、计划任务、受控浏览器 | 安装/升级/恢复可验证，后台任务可见可取消 |
| P6 | 可选扩展 | 团队共享、远程任务、插件市场、云同步 | 仅在本地安全与数据模型成熟后评估 |

## 6. 前后端接口增量

后端新增或扩展：`ExecutionGrant`、`ApprovalScope`、`TaskCheckpoint`、`RunBudget`、`Memory`、`MemoryCandidate`、`ToolRegistryEntry`、`ToolInvocation`、`Artifact` 索引和诊断快照。

前端新增或扩展：任务条、任务检查器、记忆中心、产物中心、搜索面板、连接向导、数据与隐私页、诊断中心、工具健康状态与发布更新界面。

所有新增事件必须版本化，旧客户端接收到未知字段应安全忽略；旧后端缺少新能力时前端显示降级状态，不显示虚假的“已保护/已恢复”。

## 7. 测试与发布门禁

每次功能合并应覆盖：核心单测、数据库迁移与恢复、Provider 契约测试、工具权限边界、UI 渲染、Electron E2E、三种窗口尺寸视觉回归、安装/升级/回滚冒烟测试。

以下问题阻断发布：

- 未授权写入、联网、执行或外部发布；
- 重启/重连后重复执行副作用工具；
- 用户无法查看、删除或导出自己的数据；
- 数据库迁移损坏旧数据且无法恢复；
- 审批卡、响应卡、工具卡或任务控制在任意支持窗口尺寸不可操作；
- 密钥、Cookie、私钥或未脱敏内容进入日志、记忆、搜索索引或诊断包。

## 8. 非目标与边界

- 不在 P0–P5 阶段默认引入云同步、多用户协作或远程托管 Agent。
- 不为了自动化而弱化工作区边界、审批或本地数据控制。
- 不把浏览器自动化、自动发布、Git push 等外部副作用作为默认权限。

## 9. 总体验收

当用户可以在一个明确的工作区内创建任务、理解 Agent 的计划和权限、在中断后安全继续、找到并复用所有产物、控制其记忆和数据、并完成可信的安装升级时，本计划视为达成。届时拾光不仅“能调用模型和工具”，而是一个可长期使用、可审计、可恢复的桌面 Agent。

## 11. Codex / Hermes 工具能力适配执行线

本执行线仅借鉴公开文档、许可明确的开源实现和可观察的交互模式；不复制任何闭源实现、私有协议、提示词、品牌资产或未经确认许可的工具定义。所有能力均以拾光既有 TypeScript、Electron、SQLite、项目 → 工作区 → 会话架构重新实现，并继续兼容现有响应卡、审批卡、工具卡与 Provider。

| 借鉴方向 | 拾光的落地原则 | 所属主计划阶段 |
| --- | --- | --- |
| Codex 受控执行 | 用 ExecutionGrant 真实约束读取、写入、终端与网络；界面展示实际边界 | P1 |
| Codex 审批体验 | 审批范围可选、可撤销；删除、移动、发布、Git push、凭据与全局安装强制单次确认 | P1 |
| Hermes 反思与记忆 | 将已确认的纠正转为可追溯、可编辑、可失效的候选记忆和规则 | P3 |
| 可靠工具循环 | 只重试幂等且无外部副作用的请求；失败转为检查点和明确恢复建议 | P2 / P3 |
| Provider / MCP 工具层 | 将原生 tool use、function calling 和 MCP 归一为现有工具事件与卡片 | P3 |
| 外部工具与技能 | 先检查 manifest、许可、维护者、权限与数据去向；默认禁用，审核后才能使用 | P6 |

### 11.1 实施顺序与验收

1. **P1-A：审批范围与高风险单次确认。** 审批卡提供“仅本次 / 当前任务 / 当前工作区”选择；后端保存范围并将高风险能力规范化为仅本次。已授权的低风险同能力操作只在同一任务或工作区内复用，且始终可撤销。
   - 验收：相同低风险写入在授权范围内不重复打断；删除、移动、Git push、外部发布、凭据及全局安装每次仍须确认。
2. **P2-B：工具健康与有限恢复。** 记录工具成功率、延迟、失败分类和版本；只对幂等、无副作用的网络超时/限流做有界退避重试，其他失败写入检查点并给出重试、换工具、请求输入或停止建议。
   - 验收：写入、提交和发布不会静默重试；连续失败、无进展或预算耗尽会阻止无限循环。
3. **P3-C：Hermes 记忆中心。** 区分候选、确认、已验证和失效记忆；提供来源、范围、置信度、最后验证时间、引用及删除入口。运行仅注入相关工作区记忆，当前用户指令和文件/测试事实优先。
   - 验收：用户能解释、编辑和删除每条长期记忆；机密、Cookie、密码、私钥及完整终端输出不会进入记忆。
4. **P3-D：统一 Provider / MCP 工具层。** 适配 Anthropic 原生 tool use、Gemini function calling，保留 JSON 动作协议作为降级路径；记录实际模型、工具、技能和版本，并在前端保持一致事件渲染。
   - 验收：不同 Provider 的调用和故障在界面中一致、可诊断且不会丢失任务状态。
5. **P6-E：受审核的外部工具与技能。** 安装前解析 manifest，展示许可、维护者、文件范围、联网需求与数据去向；安装后保持禁用，用户审核后才可启用，可固定版本、撤销授权、停用与回滚。
   - 验收：任何外部工具都无法绕过 ExecutionGrant、审批、工作区边界或脱敏规则。

### 11.2 当前执行状态

- 已具备：ExecutionGrant、执行预设、审批 scope 数据字段、任务检查点、Run 预算、Hermes 风格 reflection coach、记忆服务、MCP 适配与统一工具事件。
- 正在执行：P1-A。已完成审批范围选择、危险操作范围降级、同任务/同工作区低风险授权复用，以及对应类型检查、后端和 UI 回归；下一小步是把可撤销授权规则呈现在工作区设置中。
- 工具执行：P2-B 已完成第一批。工具调用现记录运行期健康度（成功/失败、连续失败、耗时、最后错误），只读的 Web、GitHub、MCP 请求在超时、限流或临时不可用时最多安全重试一次；写入、终端、提交与发布不会自动重试。
- Codex 类项目工具：已新增审批保护的 `git_commit` 与 `git_push`；前者只写本地提交历史，后者为强制单次确认的远程副作用。已有目录、读取、搜索、补丁、终端、验证、Git 状态/diff、网页、GitHub、MCP 和后台进程工具继续复用同一工作区边界。
- Hermes 开源能力对齐：以 NousResearch/hermes-agent 的技能文档为参考，采用“技能作为程序性记忆、按需加载、由审批保护写入”的模式；本轮已加入 `delete_custom_skill`，形成创建、查看、运行、记录规则和删除的最小技能管理闭环。来源与许可证需在后续外部技能导入时逐项记录。
- 后续不得直接跳到外部工具导入；必须按 P1-A → P2-B → P3-C → P3-D → P6-E 的顺序推进。

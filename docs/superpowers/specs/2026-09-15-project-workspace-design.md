# 项目与工作区设计规格

## 目标

把桌面端从“一个全局工作目录下的会话列表”升级为接近 Codex 的三级结构：`项目 → 工作区 → 任务/会话`。工作区负责确定文件修改边界；会话创建后固定绑定工作区，分支会话继承原工作区。

## 信息架构

- 项目是侧边栏中的一级分组，只负责组织工作区。
- 工作区属于一个项目，并绑定一个本地目录。
- 会话属于一个工作区。侧边栏按项目、工作区分组展示会话。
- 工作区和任务条目采用紧凑的纵向密度；任务条目目标高度约 34px。
- 保留已确认的深色电影感主题、暖橙色微光和 11 号“工作窗口”图标方向。

## 数据模型

### Project

- `id: string`
- `name: string`
- `createdAt: Date`
- `updatedAt: Date`

### Workspace

- `id: string`
- `projectId: string`
- `name: string`
- `rootPath: string`
- `createdAt: Date`
- `updatedAt: Date`

### Session

在现有字段上新增：

- `workspaceId: string`

工作区删除采用阻止策略：仍有会话时不能删除，避免历史会话失去归属。会话分支必须继承源会话的 `workspaceId`。

## 启动与迁移

- 数据库升级到 schema version 2。
- 首次迁移创建一个“默认项目”。
- 使用原设置中的 `workspaceRoot` 创建“默认工作区”。
- 所有旧会话迁移到该默认工作区。
- 迁移必须可重复执行，并保留所有历史会话、消息、任务和运行记录。

## 文件权限模型

- 相对路径默认相对于当前会话绑定的工作区解析。
- 写入、补丁、复制、移动和删除必须拒绝工作区根目录之外的目标。
- 工作区目录不存在时，历史会话仍可浏览，但发送会触发文件修改的操作前应返回清晰错误。
- 文件读取、目录查看和文件状态查询允许显式绝对路径；权限上限仍由操作系统决定。
- 项目检查、Git 状态、Git 差异和验证命令仍以当前工作区为上下文。
- 任意终端命令始终需要人工确认。第一版只能保证其工作目录位于工作区；界面必须明确提示命令可能通过绝对路径影响外部文件，不能把 `cwd` 描述成强沙箱。

## 后端接口

- 新增 `listProjects()`、`createProject(name)`。
- 新增 `listWorkspaces()`、`createWorkspace({ projectId, name, rootPath })`。
- `createSession` 改为接收 `{ title?, workspaceId }`。
- 会话 DTO 增加 `workspaceId`；工作区 DTO 增加目录可用状态。
- 运行时根据会话查找工作区根目录，不再直接使用全局设置中的 `workspaceRoot`。
- 自动创建会话时使用默认工作区；若没有可用工作区则要求用户先创建。

## 前端交互

- 侧边栏按项目和工作区嵌套显示任务。
- 新建任务从当前工作区创建；没有当前工作区时先引导新建工作区。
- 新建工作区需要名称和本地目录路径，创建后自动选中。
- 当前会话顶部展示项目名与工作区名，便于确认修改范围。
- 设置页不再把全局工作目录作为唯一运行目录；保留其作为旧版本迁移来源。

## 验收条件

- 升级旧数据库后，旧会话全部出现在默认工作区中。
- 两个工作区中的新会话分别使用各自目录执行文件工具。
- 会话分支保持原工作区。
- 写工具无法越过工作区根目录。
- 读取工具可以读取显式指定的绝对路径。
- 工作区目录失效时不会丢失历史数据，并给出可理解的错误。
- 项目、工作区和会话在侧边栏中正确分组，任务行纵向更紧凑。
- 完整测试、桌面类型检查和桌面构建通过。

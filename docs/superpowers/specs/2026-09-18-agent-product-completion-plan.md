# 拾光 Agent 产品完善计划书

## 定位

本计划承接已有的前后端适配、安全执行、持久任务、记忆循环与工具平台方案。目标不是堆叠更多功能，而是把拾光完善成一个用户可长期信任的桌面 Agent：首次能用、过程可理解、出错可恢复、数据可掌控、升级不丢工作。

## 当前能力之外还需要补齐的部分

| 方向 | 用户现在会遇到的问题 | 完成后的体验 |
| --- | --- | --- |
| 首次使用与模型配置 | 不知道从哪里开始、Provider 配置失败难排查 | 引导式创建项目、连通性检查、清晰的修复建议 |
| 任务产物与检索 | 结果散在聊天和工具输出里，之后难找 | 每个任务都有可打开、定位、复用的产物与全局搜索 |
| 稳定性与诊断 | 请求/工具失败后原因不清楚 | 可读错误、可一键复制诊断、可安全恢复 |
| 性能与离线可用 | 长会话、海量输出或网络中断会拖慢界面 | 快速加载、虚拟化、断网后仍可看历史与继续草稿 |
| 数据保护 | 不清楚本地保存什么、删除是否彻底 | 数据面板、加密选项、备份恢复和完整卸载 |
| 无障碍与本地化 | 键盘、读屏、小屏和语言体验不足 | 全键盘操作、语义化读屏、缩放与中文优先文案 |
| 发布运维 | 安装、升级、崩溃反馈不可控 | 签名更新、兼容迁移、可选匿名诊断、稳定回滚 |

## 一、首次使用与连接管理

### 1.1 新手路径

首次启动提供三步向导：创建/选择项目、选择工作区、连接模型。用户可跳过任一步进入只读演示状态，不因缺少 API Key 而被卡在空白页面。

模型连接卡应提供：Provider、模型、密钥存储位置、代理/网络状态、最近连通性检查、速率限制状态和“测试连接”按钮。密钥进入操作系统凭据存储或加密本地存储，界面只显示掩码与最后更新时间。

### 1.2 可修复的错误

将错误统一转换为用户语言：认证失败、余额/配额、模型不存在、网络、代理、超时、协议不兼容、工具权限不足。每类错误提供“发生了什么、不会影响什么、下一步怎么修”的结构化提示，技术详情折叠展示。

## 二、任务产物、搜索与可复用性

### 2.1 产物中心

现有 `Artifact` 扩展为用户能使用的产物中心：文件修改、补丁、图片、生成文档、命令结果、链接、测试报告和任务结论都可以按任务归集。每个产物显示来源、创建时间、工作区路径、验证状态和打开/复制/定位操作。

响应卡中的文件、命令、引用和下载项都应能一键进入对应产物详情，不再要求用户回滚聊天记录寻找结果。

### 2.2 搜索

提供本地全文搜索，范围可选项目、工作区、会话、任务、记忆和产物。结果显示摘要与来源，不默认把敏感字段建立索引。搜索应支持中文、文件路径、任务状态和日期过滤。

## 三、可靠性、诊断与恢复

### 3.1 运行稳定性

- 流式消息支持断线重连与幂等事件去重，避免重连后重复渲染或重复执行工具。
- 长列表、工具输出和聊天历史采用分页/虚拟列表；工具日志按需展开，避免一次性载入大量文本。
- 数据库迁移拥有版本、预检查、备份与失败回退；应用升级不能静默修改或丢弃用户数据。
- 关键后台操作有心跳、超时、取消和退出清理；应用异常退出后不自动重做存在副作用的操作。

### 3.2 诊断中心

设置中提供“诊断中心”：应用版本、平台、数据库健康度、Provider 连通性、工具健康度、最近崩溃与失败任务。用户可生成经过脱敏的诊断包，预览后再选择复制、保存或反馈。

任何遥测、崩溃报告或更新检查均默认说明用途、收集范围和关闭入口；未经选择不得上传会话、文件内容、密钥和完整工具日志。

## 四、数据、隐私与工作区治理

### 4.1 数据控制台

新增“数据与隐私”页，集中展示会话、任务、记忆、附件、日志和缓存的存储位置与占用空间。用户可按类型导出、清理缓存、删除指定项目数据、导入恢复包。

清理操作先展示影响范围与可恢复性。项目删除默认移入应用回收区，保留短暂恢复窗口；明确“永久删除”后再执行物理清理。

### 4.2 工作区健康度

工作区入口显示根目录可访问性、Git 状态、忽略规则、可写边界和最近活动。工作区移动、磁盘断开或路径失效时，任务转为 `waiting_user`，引导重新定位，而非写入未知路径。

## 五、桌面体验、无障碍与界面一致性

### 5.1 交互质量

- 为新会话、打开项目、搜索、继续任务、取消运行、切换工作区、设置等核心动作提供可发现的快捷键与命令面板。
- 所有加载、审批、失败、空状态和离线状态都有明确文案，不能只依赖颜色或旋转图标。
- 窗口缩放、窄屏、最小宽度与侧栏拖拽具有视觉回归用例，防止内容覆盖分隔条。

### 5.2 无障碍

核心卡片使用正确的按钮、列表、标题与实时区域语义；审批和模态框保持焦点锁定与 Esc 关闭；颜色对比达到可读标准；界面支持系统字体缩放、深浅主题和键盘完整操作。

中文作为默认文案需避免机器翻译式术语；日期、路径、错误信息和快捷键在中英文环境下分别测试。

## 六、发布、支持与质量门禁

### 6.1 交付链路

发布流程包含版本号、变更日志、安装包校验和、Windows 签名、更新清单、升级前备份和失败回滚。应用内展示当前版本、更新内容、下载进度和“稍后安装”。

### 6.2 质量门禁

每次发布至少运行：核心后端单测、Provider 契约测试、UI 渲染测试、Electron E2E、三种窗口尺寸的视觉回归、数据库迁移/恢复测试、权限边界测试和安装/升级冒烟测试。

建立“发布阻断”规则：数据迁移不可回滚、权限绕过、任务恢复产生副作用、关键卡片无法操作、升级后无法打开旧数据，任一出现均不能发布。

## 七、阶段排期与依赖

| 阶段 | 主题 | 交付物 | 前置依赖 |
| --- | --- | --- | --- |
| P0 | 稳定基础 | 统一错误、流式去重、迁移备份、诊断包、数据脱敏 | 现有事件与数据库 |
| P1 | 可用性 | 首次向导、Provider 连接管理、产物中心、搜索 | P0 的状态与诊断 |
| P2 | 信任与控制 | 数据控制台、工作区健康、快捷键、无障碍与视觉回归 | 安全/记忆/任务方案 |
| P3 | 可交付产品 | 签名、自动更新、回滚、发布门禁与反馈通道 | P0–P2 测试覆盖 |
| P4 | 后续扩展 | 团队共享、远程任务、插件市场、可选云同步 | 本地权限与数据模型稳定 |

## 非目标

- 不在基础稳定前引入默认云同步、多人协作或远程托管执行。
- 不为追求“自动化”降低审批、工作区边界或数据保护标准。
- 不以隐藏诊断/遥测为代价换取易用性。

## 验收标准

- 新用户在没有配置经验的情况下，能在五分钟内完成项目、工作区和模型连接，失败时知道如何修复。
- 用户能在任何时间找到任务产物、了解其来源并打开或复用它。
- 网络中断、应用重启、Provider 失败和数据库迁移失败不会悄悄造成重复副作用或数据丢失。
- 用户可以查看、导出和删除本地数据；诊断与遥测始终经过脱敏和用户选择。
- 核心体验在键盘、读屏、窗口缩放和窄屏下均可完整完成。
- 每个正式版本均有可验证的安装、升级、回滚与恢复路径。

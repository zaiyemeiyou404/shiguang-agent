# Agent 记忆、任务循环与工具平台设计规格

## 目标

让拾光 Agent 从一次性对话助手，成为可长期协作但始终可控的本地 Agent：能记住经确认的项目知识，能把复杂工作拆成有限、可恢复的循环，并能安全、可审计地使用工具。

本方案不改变既有“项目 → 工作区 → 会话”的层级，也不替换已有响应卡、审批卡、工具卡和事件流；新增能力必须通过现有前后端事件体系渐进接入。

## 用户体验

用户只需要看到三件事：

1. **它记住了什么。** 会话顶部的“记忆”入口显示本次使用的工作区规则、项目事实与用户确认的偏好；任何记忆都能查看来源、编辑、停用或删除。
2. **它正在做什么。** 任务条显示“计划 / 执行 / 验证 / 等待确认 / 已停止”，以及已用预算和下一步；不会出现无限转圈的不可解释状态。
3. **它准备调用什么工具。** 工具卡显示用途、影响范围、数据去向、权限和实际结果；高风险动作在执行前等待确认。

## 一、分层记忆

### 1.1 范围和优先级

| 类型 | 示例 | 生命周期 | 优先级 |
| --- | --- | --- | --- |
| 当前指令 | “这次只改前端” | 当前任务 | 最高 |
| 已验证事实 | `package.json` 的脚本、测试结果 | 持续到失效 | 高 |
| 工作区记忆 | 技术栈、目录约定、启动方式 | 工作区长期 | 中 |
| 项目记忆 | 产品术语、发布流程、团队约定 | 项目长期 | 中 |
| 用户偏好 | 中文回复、界面风格 | 用户主动启用 | 低 |

冲突时遵循：当前用户指令 > 已验证文件或工具结果 > 记忆 > 模型推断。模型推断不能直接成为长期记忆。

### 1.2 数据结构

每条 `Memory` 保存：`id`、范围、内容摘要、来源类型、来源链接或事件 ID、置信度、创建/验证/失效时间、敏感等级、状态（active / stale / archived）。

不保存密码、令牌、Cookie、私钥、完整终端输出和未经用户同意的个人信息。检测到敏感内容时只保留“存在敏感信息，未保存”的提示。

### 1.3 写入与检索

- Agent 在完成任务后只能创建“建议记住”候选项；用户可接受、修改或忽略。
- 文件、测试或用户明确确认的事实可标为“已验证”。文件变更、测试失败或用户否定后，相关记忆自动标记为 `stale`，不再默认注入上下文。
- 每次任务仅检索与工作区、目标、相关路径匹配的少量记忆，并将“已使用记忆”显示在任务检查器内。
- 设置页提供记忆中心：搜索、范围筛选、来源追溯、导出、编辑、失效、删除；删除后立即停止检索。

## 二、任务循环与恢复

### 2.1 有限循环

每个任务由 `TaskLoopController` 管理，不允许模型自行无限调用。状态流转：

```text
planned → running → verifying → completed
                 ├→ waiting_approval
                 ├→ waiting_user
                 └→ blocked / cancelled
```

单次循环只完成一个可验证子步骤：阅读与定位、规划、一次工具链、验证或汇报。每轮完成后写入事件和检查点。

### 2.2 预算与停止规则

`RunBudget` 包含最大时长、模型调用次数、工具调用次数、重试次数、令牌/费用和后台存活时间。以下情形必须停止并转为 `blocked`：

- 同一工具或错误连续重复超过阈值；
- 没有文件、测试、工具结果或用户确认等可观察进展；
- 预算耗尽、权限不足、工作区范围变化；
- 出现删除、外部发布、提交表单、Git push 等未获批准的副作用。

恢复时不自动重放命令或副作用工具。前端先展示最后检查点、下一步、剩余预算和待确认权限，由用户点击继续。

### 2.3 子任务和计划任务

- 子任务默认只读，并继承工作区边界，不继承写入、联网和外部发布许可。
- 子任务必须回传结构化交接：目标、事实、产物、验证、阻塞项、建议下一步。
- 定时/轮询任务必须声明频率、结束条件、最长存活时间、通知方式和取消入口；不可创建无期限后台循环。

## 三、工具平台

### 3.1 工具注册表

所有内置工具、MCP、技能与用户脚本通过统一注册表声明：版本、输入输出 Schema、幂等性、超时、能力标签、数据去向、最小权限、可用工作区和域名策略。

能力标签至少包括：文件读取、文件写入、终端、网络、浏览器、凭据、Git、安装依赖、外部发布。

### 3.2 调用规则

1. 先检查工具注册表和工作区 `ExecutionGrant`。
2. 读取操作优先；官方 API 优先于页面模拟；本地工具优先于远程工具。
3. 不满足权限时生成审批卡，显示目标、命令/域名、影响和授权时限。
4. 工具返回后写入统一事件：`tool_started`、`tool_progress`、`tool_result`、`tool_retry`、`tool_blocked`、`tool_cancelled`。
5. 只有幂等且无外部副作用的工具可以自动重试；写入、提交、发送、付款、发布永不静默重试。

### 3.3 技能治理

技能按版本安装与启用，安装界面展示维护者、所需工具、联网需求、文件范围和数据去向。技能只能提供工作流和声明，不能绕过审批或工作区边界。每个任务记录实际使用的技能版本，支持固定、禁用和回滚。

## 四、前后端接入

后端新增或扩展 `Memory`、`MemoryCandidate`、`TaskCheckpoint`、`RunBudget`、`ToolRegistryEntry`、`ToolInvocation`。现有 Task、Run、Event、Artifact 保持兼容。

前端在当前会话标题下增加紧凑任务条；详情放入任务检查器抽屉，避免挤压聊天、响应卡与审批卡。工具卡沿用现有渲染结构，只增加权限、来源、进度、重试和结果摘要字段。

## 五、实施顺序

1. 定义数据模型与事件契约；为敏感信息打码并建立工具注册表。
2. 实现任务预算、检查点、停止/继续/取消与前端任务条。
3. 实现工作区与项目记忆、候选写入审核、记忆中心和按需检索。
4. 统一 MCP/内置工具/Provider 工具事件，补齐健康度与安全重试。
5. 实现子任务、计划任务，以及 Electron 端到端恢复与视觉回归测试。

## 验收标准

- 用户可知道一条记忆的内容、范围、来源与最后验证时间，并能立即删除。
- 重启应用后，未完成任务恢复为“可继续”，不自动产生新的副作用。
- 长任务显示预算与进度，循环卡住或重复时能自动安全停止。
- 工具调用能追溯到版本、权限、目标、数据去向和事件结果，敏感内容不落入卡片、记忆或导出包。
- 现有会话、响应卡、操作确认、工具调用和多 Provider 前端渲染不回归。

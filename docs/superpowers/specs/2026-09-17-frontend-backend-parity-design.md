# 前后端功能等价对接设计规格

## 目标

在保留当前 Codex 风格的“项目 → 工作区 → 任务/会话”界面与已确认视觉主题的前提下，把旧前端已经提供的全部用户能力接回新版界面。验收口径是功能等价，而不是旧布局复刻：旧版能查看、执行、恢复或配置的操作，在新版中必须有明确入口、完整状态反馈和失败提示。

## 设计原则

- 当前项目、工作区、任务层级保持不变；会话继续永久绑定工作区。
- 中央区域以对话为主，运行事件按“响应、思考、工具、审批、系统、错误”转换成可读卡片。
- 诊断、运行历史和产物放入按需展开的检查器，不长期挤压聊天宽度。
- 高风险动作必须在原位显示操作对象、影响范围、警告和通过/拒绝按钮。
- 历史快照与实时事件合并时按 `event.id` 去重、按 `seq` 排序，切换运行后不得继续接收旧运行事件。
- 所有异步动作都有 loading、成功、空状态和错误状态；重复点击不得产生重复请求。
- 后端现有业务语义优先复用，仅补齐强类型事件载荷、订阅生命周期和前端所需的稳定快照。

## 功能等价矩阵

| 旧前端能力 | 新版入口 | 数据/动作来源 | 验收要点 |
| --- | --- | --- | --- |
| Home / Workspace / Review | 左侧主导航与任务页 | 本地 UI 状态、会话快照 | 三个入口均可达，不丢失当前项目/工作区/任务选择 |
| 会话搜索、固定、焦点、进行中、归档 | 项目/工作区下的紧凑任务列表 | `listSessions`、本地固定状态 | 过滤结果、状态徽标、固定排序与旧版一致 |
| 新建、重命名、归档/恢复、删除、分支 | 任务行菜单与对话顶部菜单 | 会话 IPC | 成功后列表和当前选择立即同步，失败保留上下文并提示 |
| 历史消息与助手响应 | 中央对话流 | `getWorkspaceSnapshot`、运行事件 | 内容、角色、时间、运行归属正确；历史与直播不重复 |
| 思考过程 | 可折叠活动卡 | `thinking` | 默认收起，可查看原始内容，不抢占主要响应层级 |
| 工具调用与工具结果 | 成对工具卡 | `tool_call`、`tool_result` | 依据调用标识配对；显示工具、参数、状态、结果、耗时/时间；孤立事件仍可显示 |
| 操作确认 | 对话内审批卡 + Review 汇总页 | approvals API 与 approval 事件 | 显示能力、目标、预览、风险；通过/拒绝防重复；决定后状态即时更新并恢复运行 |
| 错误、停滞、上下文压缩 | 对话内系统卡与顶部提示 | error/system/context 事件、运行状态 | 信息可读、可定位所属运行；停滞只提示不误报失败 |
| 运行阶段、事件统计、最近活动 | 右侧可折叠运行检查器 | 运行与事件快照 | 当前状态、阶段、事件数、开始/结束时间与旧版一致 |
| 失败诊断与修复建议 | 错误卡操作区与检查器 | 前端诊断模型、运行原因、工具结果 | 可复制证据、写入修复提示、带提示继续、重试或分支 |
| 运行历史 | 检查器中的运行列表 | session detail | 可切换运行、复制提示、查看产物、重试、分支 |
| 产物 | 对话关联卡 + 检查器产物区 | artifacts API | 可跳转所属运行，复制 URI，本地打开/定位，网络地址打开 |
| 附件 | 输入框附件选择与移除 | `pickAttachments`、`sendUserMessage` | 发送前可移除；空文本但有附件时可发送；发送失败保留草稿和附件 |
| 取消、重试、继续工作 | 对话顶部与错误卡 | run actions | 状态限制正确，进行中的动作不可重复触发 |
| Provider/模型设置与连接测试 | 设置抽屉 | settings APIs | 新增、复制、重命名、删除、排序、导入导出、测试、保存与回退均可用 |
| 工作区范围提示 | 对话标题与危险操作卡 | workspace DTO | 始终能看到当前项目/工作区；修改动作只在绑定工作区内生效 |

## 数据契约

### 事件载荷

把 `DesktopEvent.payload: unknown` 收紧为按 `kind` 区分的联合类型，至少覆盖：

- `message`: `role`、`content`
- `thinking`: `content` 或 `message`
- `tool_call`: `toolCallId`、`tool`、`arguments`
- `tool_result`: `toolCallId`、`tool`、`output`、`isError`
- `error` / `system`: `message`、可选 `code`
- `approval_request`: `approvalId`、`capability`、`preview`
- `approval_granted` / `approval_denied`: `approvalId`、可选 `message`
- `context_compacted`: `message`、可选压缩统计

旧数据缺字段时由适配器产生安全的降级文案，不允许卡片渲染崩溃。

### 审批预览

`DesktopApproval.request` 必须被规范化为可显示模型：标题、摘要、命令或目标路径、工作目录、影响范围、警告、结构化参数和原始载荷。前端不根据任意嵌套对象猜测主要风险字段；后端适配器负责兼容历史请求形状。

### 实时订阅

- 渲染进程订阅运行时获得唯一订阅 ID。
- 取消订阅必须同时移除渲染监听器与主进程中的服务监听器。
- 前端先建立订阅再读取历史，之后合并去重，避免快照与直播之间出现事件缺口。
- 切换任务、切换运行、组件卸载或窗口销毁时均清理订阅。

## 状态边界

- `useDesktopSessions` 只负责项目、工作区、任务选择与任务生命周期。
- `useSessionWorkspace` 负责当前任务快照、运行选择、审批与产物刷新。
- `useRunActivity` 负责事件历史、实时订阅、去重排序与流状态。
- 纯函数 `buildActivityItems` 把后端事件转换为渲染模型；React 卡片不直接解析 `unknown` 载荷。
- 每个审批 ID、运行动作和设置保存分别维护 pending 状态，避免一个动作锁死整个界面。

## 非目标

- 不复刻旧前端的固定三栏尺寸和旧视觉样式。
- 不改变工作区读写权限模型，也不把终端工作目录描述为安全沙箱。
- 不在本次改造中更换 Agent 运行引擎、Provider 协议或数据库模型。
- 不新增旧前端从未支持的协作、云同步或富文本编辑功能。

## 验收标准

- 功能等价矩阵每一行都有自动化测试或明确的桌面手工验收步骤。
- 响应卡、工具调用/结果卡、审批卡、错误/上下文卡均能从真实后端事件渲染。
- 审批通过与拒绝不会重复提交，决定后卡片、运行状态和待审数量一致。
- 快速切换两个运行不会串流、丢事件或累积后台订阅。
- 发送失败不会丢失输入和附件；成功发送后才清空。
- 旧会话、历史运行、审批和产物无需迁移即可在新前端读取。
- `npm test`、UI 测试、桌面类型检查和桌面构建全部通过。
